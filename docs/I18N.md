# Интернационализация (i18n) - MiniPhone

## 📋 Обзор

Проект использует систему переводов на основе **JSON** файлов. Язык интерфейса автоматически определяется по `language_code` из Telegram WebApp.

## 🚀 Быстрый старт

Переводы загружаются автоматически при сборке проекта. Никаких дополнительных шагов не требуется.

### 2. Использование в компонентах

```tsx
import { useTranslation } from '@/shared/hooks/useTranslation';

function MyComponent() {
  const t = useTranslation();
  
  return (
    <div>
      <p>{t('Loading...')}</p>
      <button>{t('Confirm')}</button>
    </div>
  );
}
```

## 🌍 Поддерживаемые языки

- **ru** - Русский
- **en** - Английский (по умолчанию)

Язык определяется автоматически по `language_code` из `window.Telegram.WebApp.initDataUnsafe.user.language_code`.

## 📁 Структура файлов

```
src/shared/lib/i18n/
├── translations/
│   ├── ru.json        # Русские переводы
│   └── en.json        # Английские переводы
├── loader.ts          # Загрузчик переводов
├── I18nProvider.tsx   # React провайдер для переводов
├── I18nWrapper.tsx    # Обертка с определением языка из WebApp
└── index.ts           # Утилиты для работы с языками
```

## 📝 Добавление новых переводов

### 1. Добавьте строку в JSON файлы

Откройте файл `src/shared/lib/i18n/translations/ru.json` и добавьте:

```json
{
  "Your text": "Ваш текст"
}
```

Аналогично для `en.json`:

```json
{
  "Your text": "Your text"
}
```

### 2. Используйте в коде

```tsx
const t = useTranslation();
<p>{t('Your text')}</p>
```

Готово! Никакой компиляции не требуется.

## 🔧 Формат JSON файлов

### Базовый формат

```json
{
  "Original text": "Переведенный текст"
}
```

### Пример полного JSON файла

```json
{
  "Loading...": "Загрузка...",
  "Error": "Ошибка",
  "Success": "Успешно",
  "Confirm": "Подтвердить",
  "Checking authentication...": "Проверка аутентификации...",
  "MiniPhone": "MiniPhone",
  "Calls": "Звонки"
}
```

### Множественное число

Для поддержки множественного числа можно использовать ключи с суффиксами:

```json
{
  "item_one": "элемент",
  "item_few": "элемента",
  "item_many": "элементов"
}
```

**Использование в коде:**

```tsx
const t = useTranslation();
const count = 5;
const key = count === 1 ? 'item_one' : count < 5 ? 'item_few' : 'item_many';
<p>{t(key)}</p>
```

### Контекст

Для разных контекстов используйте префиксы:

```json
{
  "button.save": "Сохранить",
  "menu.save": "Сохранить как..."
}
```

**Использование:**

```tsx
const t = useTranslation();
<button>{t('button.save')}</button>
```

## 🛠️ Технические детали

### Загрузка переводов

Переводы загружаются из JSON файлов при импорте модуля. JSON файлы обрабатываются webpack и включаются в бандл, что обеспечивает:
- Быструю загрузку (нет дополнительных HTTP запросов)
- Простоту использования (стандартный JSON формат)
- Поддержку TypeScript (автодополнение для ключей)

### Определение языка

Язык определяется в следующем порядке:

1. `language_code` из `window.Telegram.WebApp.initDataUnsafe.user.language_code`
2. Если код начинается с `ru` → русский язык
3. Иначе → английский (по умолчанию)

**Примеры:**
- `ru` → русский
- `ru-RU` → русский
- `en` → английский
- `en-US` → английский
- `de` → английский (fallback)

### Кэширование

Переводы кэшируются после первой загрузки для повышения производительности.

## 📚 API

### `useTranslation()`

Хук для получения функции перевода.

```tsx
const t = useTranslation();
const text = t('Loading...');
```

**Возвращает:** `(msgid: string) => string`

### `I18nProvider`

Провайдер контекста для переводов.

```tsx
<I18nProvider languageCode="ru">
  <App />
</I18nProvider>
```

**Props:**
- `languageCode?: string | null` - код языка (например, "ru", "en")
- `defaultLanguage?: Language` - язык по умолчанию (по умолчанию "en")
- `children: ReactNode`

### `I18nWrapper`

Обертка, автоматически определяющая язык из Telegram WebApp.

```tsx
<I18nWrapper>
  <App />
</I18nWrapper>
```

**Использование:** Обычно используется в `_app.tsx` для автоматического определения языка.

### `getLanguageFromCode(languageCode?: string | null): Language`

Утилита для преобразования кода языка в поддерживаемый язык.

```tsx
import { getLanguageFromCode } from '@/shared/lib/i18n';

const lang = getLanguageFromCode('ru-RU'); // 'ru'
const lang2 = getLanguageFromCode('en-US'); // 'en'
const lang3 = getLanguageFromCode(null); // 'en' (default)
```

## 🔄 Workflow разработки

### 1. Добавление новой строки для перевода

1. Добавьте строку в код:
   ```tsx
   <p>{t('New feature')}</p>
   ```

2. Добавьте переводы в `.po` файлы:
   ```po
   # ru.po
   msgid "New feature"
   msgstr "Новая функция"
   
   # en.po
   msgid "New feature"
   msgstr "New feature"
   ```

3. Скомпилируйте (опционально, для production):
   ```bash
   npm run i18n:compile
   ```

### 2. Обновление существующих переводов

1. Отредактируйте JSON файлы
2. Изменения применятся автоматически при следующей сборке/перезагрузке

### 3. Добавление нового языка

1. Создайте новый JSON файл: `src/shared/lib/i18n/translations/xx.json`
2. Добавьте язык в `src/shared/lib/i18n/index.ts`:
   ```ts
   export type Language = 'ru' | 'en' | 'xx';
   ```
3. Обновите функцию `getLanguageFromCode()` для поддержки нового языка
4. Импортируйте новый файл в `loader.ts`:
   ```ts
   import xxTranslations from './translations/xx.json';
   ```
5. Добавьте в `translationFiles`:
   ```ts
   const translationFiles = {
     ru: ruTranslations,
     en: enTranslations,
     xx: xxTranslations,
   };
   ```

## 🐛 Отладка

### Проблема: Переводы не загружаются

**Решение:**
1. Проверьте, что `.po` или `.mo` файлы существуют
2. Проверьте консоль браузера на наличие ошибок
3. Убедитесь, что `I18nWrapper` обернут вокруг приложения

### Проблема: Язык определяется неправильно

**Решение:**
1. Проверьте `language_code` в `window.Telegram.WebApp.initDataUnsafe.user.language_code`
2. Проверьте функцию `getLanguageFromCode()` в `src/shared/lib/i18n/index.ts`

### Проблема: Строка не переводится

**Решение:**
1. Убедитесь, что строка добавлена в JSON файлы
2. Проверьте, что ключ точно совпадает с используемой строкой (регистр важен)
3. Перезагрузите страницу или пересоберите проект

### Проблема: Ошибка при загрузке переводов

**Решение:**
1. Проверьте синтаксис JSON файлов (валидный JSON)
2. Убедитесь, что файлы импортированы в `loader.ts`
3. Проверьте, что ключи совпадают во всех языковых файлах

## 💡 Best Practices

### 1. Используйте ключи вместо полных предложений

❌ Плохо:
```tsx
t('Are you sure you want to delete this item?')
```

✅ Хорошо:
```tsx
t('delete.confirmation')
```

И в JSON:
```json
{
  "delete.confirmation": "Вы уверены, что хотите удалить этот элемент?"
}
```

### 2. Группируйте переводы по контексту

Используйте префиксы в JSON файлах для группировки:

```json
{
  "common.loading": "Загрузка...",
  "auth.checking": "Проверка аутентификации...",
  "user.username": "Имя пользователя"
}
```

### 3. Не переводите технические термины

```tsx
// Не переводите названия продуктов, API endpoints и т.д.
<p>{t('MiniPhone')}</p> // Оставляем как есть
<p>{t('API endpoint')}</p> // Можно перевести
```

### 4. Используйте префиксы для одинаковых строк

Если одна строка имеет разные значения в разных контекстах, используйте префиксы:

```json
{
  "button.save": "Сохранить",
  "file.save": "Сохранить файл"
}
```

## 🎓 Примеры

### Базовое использование

```tsx
import { useTranslation } from '@/shared/hooks/useTranslation';

function WelcomeScreen() {
  const t = useTranslation();
  
  return (
    <div>
      <h1>{t('Welcome')}</h1>
      <p>{t('Loading...')}</p>
      <button>{t('Continue')}</button>
    </div>
  );
}
```

### Использование с условиями

```tsx
function StatusMessage({ isLoading, error }) {
  const t = useTranslation();
  
  if (isLoading) {
    return <p>{t('Loading...')}</p>;
  }
  
  if (error) {
    return <p>{t('Error')}: {error.message}</p>;
  }
  
  return <p>{t('Success')}</p>;
}
```

### Динамические строки

```tsx
function UserGreeting({ userName }) {
  const t = useTranslation();
  
  // Для динамических строк используйте шаблоны
  return <p>{t('Hello')}, {userName}!</p>;
}
```

## ⚙️ Конфигурация

### next.config.mjs

Стандартная конфигурация Next.js поддерживает импорт JSON файлов из коробки. Дополнительная настройка не требуется.

### package.json

Скрипты для компиляции переводов не требуются, так как JSON файлы используются напрямую.

## 🔐 Безопасность

- Переводы загружаются только из проверенных источников (файлы в проекте)
- Нет динамической загрузки переводов из внешних источников
- `.po` и `.mo` файлы включены в репозиторий для контроля версий
